## 1. 왜 만드는가

미국 주식 정보 앱·웹 서비스를 만드는 회사의 프론트엔드 포지션에 지원하기 위한 증명 과제다. 이 포지션은 **React Native(Expo) 앱과 Next.js 웹 양쪽에서 상용 서비스를 개발·배포한 경험**을 자격요건으로 두고 있다. 지원자에게는 그 경험이 없다.

지원자의 강점은 **AI를 활용해 처음 보는 스택을 빠르게 도입하고, 틀리지 않게 개선해 나가는 것**이다. 전 직장에서 팀 커밋의 79%를 AI가 공동 작성하는 환경을 운영하면서 spec·lint·검증 장치로 AI 산출물을 걸러 낸 경험이 있다.

이 과제는 "RN·Next 경험이 있다"를 주장하려는 것이 아니다. **그 강점이 낯선 스택에서도 통한다는 걸 공개된 과정으로 보여 주는 것**이 목적이다.

### 성공 기준
- 면접관이 저장소를 연 **30초 안에** "이 사람 RN·Next도 금방 하겠네"라고 느낀다 [결정]
  - README 맨 위: 휴대폰(Expo)과 웹(Next.js)에서 같은 종목 차트가 실시간으로 움직이는 짧은 영상 [제안]
  - 그 아래 한 줄: 며칠 만에 만들었는지, AI가 틀린 코드를 장치가 몇 번 잡았는지 [제안]
  - 폴더 구조만 봐도 앱과 웹이 디자인 토큰·데이터 계층을 공유한다는 게 드러남 [제안]
- **코드 + 배포**까지 된다 [결정]
  - 웹: Vercel에 배포된 링크 [결정]
  - 앱: Expo Go로 QR을 찍어 바로 실행(EAS Update 게시) [결정]
    - 안드로이드 실기기·iOS 시뮬레이터만 해당. 아이폰 실기기는 App Store의 Expo Go가 SDK 54에서 멈춰 SDK 58 앱을 열 수 없으므로 시연 영상으로 대체 [결정, #1]
- 경력기술서에 개인 프로젝트로 적을 수 있는 수준 [결정]
- 일하는 방식이 저장소에 남는다: **spec → 이슈 → 이슈당 PR → CI 게이트 → 머지** [결정]

### 기한
- **1주 안에 지원 메일을 보낸다** [결정]. 6일차까지 README·경력기술서 반영을 끝낸다.

## 2. 목표 / 비목표 / 반목표

### 목표
1. Turborepo 모노레포: `apps/web`(Next.js App Router), `apps/mobile`(Expo Router), `packages/*`(공유 코드) [제안]
2. **관심 종목 목록**과 **종목 상세의 실시간 시세 차트**를 웹·앱 모두에서 제공 [제안]
3. 웹 종목 상세는 **ISR + SEO 메타**(종목별 title·description·OG) [제안]
4. 앱 안에 **WebView 화면** 1개 + Native ↔ WebView **메시지 규격**(예: 테마 전달, WebView → 앱 이벤트) [제안]
5. **성능 측정 → 개선 이슈 → 전후 수치**를 최소 2건 남김 [제안]
   - 웹: Vercel 배포본의 LCP·CLS (Lighthouse 또는 Web Vitals)
   - 앱: 실시간 차트 갱신 시 렌더 비용(재렌더 횟수·프레임 드랍 등, 측정 방법은 [빌더])
6. AI가 틀린 지점을 `docs/ai-log.md`에 이슈·PR 링크와 함께 기록 [제안]

### 비목표 (1주 범위에서 하지 않음)
- 아이폰 TestFlight, 안드로이드 APK 배포 [결정: Expo Go로 대체]
- 로그인·회원·커뮤니티 [제안]
- 실제 시세 API **필수** 연동. 기본은 시뮬레이션 시세, 실제 API는 선택 기능 [제안]
- 앱·웹 **UI 컴포넌트 코드 공유**(react-native-web 등). 공유는 디자인 토큰과 데이터 계층까지 [제안]

### 반목표 (동작해도 실패로 보는 것)
- 특정 회사 서비스의 이름·화면·데이터를 베낀 것처럼 보이는 결과물
- 전 직장 코드·문서·스킬 파일을 복사한 흔적. 모든 파일은 이 저장소에서 새로 작성한다
- 커밋·PR이 "AI가 한 번에 다 만든" 덩어리로 보이는 것. 이슈 단위로 쪼개진 흐름이 보여야 한다
- 미국 장이 닫힌 시간에 시연하면 화면이 멈춰 있는 것
- API 키·토큰이 저장소에 커밋되는 것

## 4. 구조 (정해진 부분)

```
apps/
  web/        Next.js (App Router, TypeScript) — Vercel 배포
  mobile/     Expo (Expo Router, TypeScript) — EAS Update 게시, Expo Go로 열람
packages/     (필요해질 때 이슈로 만든다)
  tokens      디자인 토큰: 색·타이포·간격. 웹은 CSS 변수, 앱은 TS 상수로 소비 [제안]
  market      시세 도메인: 종목 타입, Zod 스키마, 시뮬레이션 시세 생성기, TanStack Query 훅 [제안]
docs/
  design.md   이 문서
  spec/       기능별 spec (템플릿: spec/_template.md)
  ai-log.md   AI가 틀린 지점 기록 (첫 기록 때 생성)
```

### 시뮬레이션 시세 [제안]
- 같은 시각이면 웹과 앱이 **같은 가격**을 보여 주도록, 시각을 입력으로 하는 결정적(deterministic) 생성기를 `packages/market`에 둔다
- 전달 방식(웹 SSE 엔드포인트 vs 클라이언트 로컬 생성, 앱의 스트리밍 수신 방법)은 [빌더]. 단, 장 마감 시간에도 움직여야 한다

## 5. 작업 흐름 (정해진 부분)

1. 기능마다 `docs/spec/<기능>.md`를 먼저 쓴다(목적·화면·데이터·수용 기준·범위 밖)
2. spec의 수용 기준을 GitHub 이슈로 쪼갠다. 라벨(`type:*`, `area:*`)과 마일스톤 `v1`을 단다
3. 이슈당 브랜치 → PR(`Closes #n`) → CI(lint·typecheck·test·web build) 통과 → squash 머지
4. AI가 틀린 코드를 장치(타입·lint·테스트·리뷰·화면 확인)가 잡았으면 PR에 `ai-miss` 라벨을 달고 `docs/ai-log.md`에 한 줄 남긴다
5. 성능 개선은 `type:perf` 이슈로 따로 만들고, 이슈 본문에 측정 방법과 개선 전 수치, PR에 개선 후 수치를 적는다

## 7. 설계 검토에서 정한 것

설계 문서를 다른 빌더가 읽고 "추측해야 하는 곳"을 뽑은 뒤 정리한 결과.

| 질문 | 결정 | 누가 |
|---|---|---|
| 종목 데이터 | **실제 티커(AAPL 등) + 시뮬레이션 시세.** 화면에 "시뮬레이션 시세"를 표시하고, SEO 메타(title·description·OG)는 구현하되 `robots: noindex`로 검색 노출을 막는다 — 실제 종목의 가짜 시세가 검색에 잡히지 않게 | 지원자 |
| Expo Go로 못 여는 경우 | **README 시연 영상으로 대체.** APK는 만들지 않는다(비목표 유지). 1일차 배포 연결 때 다른 기기·계정에서 열리는지 확인하고 결과를 이슈에 남긴다. → 확인 결과(#1): 아이폰 실기기는 열 수 없다(App Store Expo Go는 SDK 54까지). SDK 58을 유지하고 아이폰만 영상으로 대체한다. SDK를 54로 내리면 이번엔 안드로이드가 막힐 수 있어서다(Expo Go 한 빌드는 SDK 한 버전만 지원) | 지원자 |
| WebView에 띄울 것 | 배포된 `apps/web`의 종목 페이지를 **임베드 모드**(예: `?embed=1`, 헤더 숨김)로 띄운다. 메시지 타입은 `packages/`에 두어 웹·앱이 같이 쓴다. 공고 우대사항의 "하이브리드 앱 내 웹 통합"과 맞추기 위함. 웹 배포가 먼저 되어야 하므로 1일차에 배포를 연결한다 | 설계자 판단 |
| 테마 | 라이트·다크 두 가지를 토큰에 정의하고, 앱이 WebView에 현재 테마를 전달하는 것을 메시지 규격의 첫 예로 삼는다 | 설계자 판단 |
| 관심 종목 | **고정 목록**(10개 안팎). 추가·삭제·저장 기능은 없다. 웹 종목 상세 ISR은 이 목록을 미리 만들고, 목록에 없는 티커는 404 | 설계자 판단 |
| 성능 개선 전 수치 | **연출하지 않는다.** 일부러 느린 버전을 만들지 않고, 실제 구현을 부하 조건(고빈도 갱신, 시리즈 수 증가 등)에서 측정한다. 개선할 게 없으면 "측정했고 문제없음"도 그대로 기록한다 | 설계자 판단 |

- 테스트 범위(최소: `packages/market`의 생성기·스키마 단위 테스트)
