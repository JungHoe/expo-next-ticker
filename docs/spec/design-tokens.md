# 디자인 토큰

- 상태: 확정
- 관련 이슈: #7, #8 (spec 작성 #6)

## 1. 목적
웹과 앱이 같은 색, 글꼴, 선, 간격을 쓰게 한다. 화면을 볼 때 "AI가 기본값으로 만든 화면"이 아니라 하나의 재료로 짠 화면으로 읽히게 하는 기반이다.

## 2. 화면
| 플랫폼 | 화면 | 구성 |
|---|---|---|
| 웹 | 모든 화면 | `:root`의 CSS 변수로 토큰을 쓴다. 다크는 `prefers-color-scheme`를 따른다 |
| 앱 | 모든 화면 | TS 상수로 토큰을 쓴다. 다크는 `useColorScheme()`을 따른다 |

## 3. 데이터
- 위치: `packages/tokens`. 플랫폼 중립 TS가 원본이고, 웹 CSS 변수와 앱 상수는 이 원본에서 만든다
- 재료: Hallmark 테마 **Almanac**(지원자 선택)의 종이, 잉크, 글꼴, 선, 면. 강조색(마젠타)은 쓰지 않는다(§7)

### 색 (라이트)
| 토큰 | 값 | 쓰임 |
|---|---|---|
| `paper` | `oklch(84% 0.012 245)` | 화면 바탕(슬레이트) |
| `paper-2` | `oklch(81% 0.012 245)` | 선택된 행, 우물(well) |
| `sheet` | `oklch(93.5% 0.008 245)` | 표·상세가 놓이는 "인쇄된 종이" |
| `ink` | `oklch(16% 0.020 245)` | 제목, 숫자 |
| `ink-2` | `oklch(24% 0.018 245)` | 본문 |
| `muted` | `oklch(38% 0.016 245)` | 라벨, 축 글자 |
| `rule` | `oklch(73% 0.013 240)` | 1px 구분선, 차트 격자 |
| `rule-2` | `oklch(32% 0.018 240)` | 2px 굵은 선(표 머리 아래), 기준가 선 |
| `up` | `oklch(42% 0.16 25)` | 상승(빨강) |
| `down` | `oklch(42% 0.15 262)` | 하락(파랑) |

### 색 (다크)
Almanac의 "잉크 띠"(남색 바탕 + 종이색 글자)를 다크의 출발점으로 삼는다. 값은 구현하면서 정하되 §5의 대비 기준을 통과해야 한다. `up`·`down`은 명도를 올려 다시 맞춘다.

### 글꼴
| 역할 | 글꼴 | 규칙 |
|---|---|---|
| 제목 | Hanken Grotesk 600 | 자간 -0.02em, 문장형 대소문자 |
| 본문·라벨·표 머리 | Newsreader 400/500 | 라벨은 한 단계 작게, `muted`. 대문자 자간 라벨 금지 |
| 숫자 | IBM Plex Mono 400/500 | `tabular-nums`, 오른쪽 정렬. 숫자 외에는 쓰지 않는다 |
| 한글 | 시스템 고딕(대체 글꼴) | 위 글꼴에 한글이 없으므로 기기 기본 고딕이 대신 그린다 |

### 형태
- 간격: 4px 배수
- 선: `rule-hair` 1px(행 구분), `rule-bar` 2px(제목·표 머리 아래). 그보다 굵은 선은 없다
- 모서리: 면은 0, 컨트롤은 최대 2px
- 그림자, 그라데이션, 박스 카드, 이모지: 쓰지 않는다
- 깊이는 그림자 대신 선 하나와 종이 한 단계(`paper` → `paper-2`)로 표현한다

## 4. 동작 규칙
| 상태 | 웹 | 앱 |
|---|---|---|
| 라이트·다크 전환 | 시스템 설정을 따른다. 전환 버튼 없음 | 시스템 설정을 따른다(`userInterfaceStyle: automatic`) |
| 글꼴 로딩 전 | 대체 글꼴로 먼저 그린다. 레이아웃이 밀리지 않게 한다 | 글꼴이 준비될 때까지 스플래시를 유지한다 |
| 모션 | 상태 변화만 표시한다. 숫자 깜빡임·카운트업·등장 애니메이션 없음 | 같음 |

## 5. 수용 기준
앱 화면은 Expo 웹 미리보기(`expo start --web`)로 배치·색·차트를 확인한다. **(기기)** 표시 기준은 브라우저로 판정할 수 없는 네이티브 동작이라, 안드로이드 기기를 쓸 수 있을 때 #4와 함께 몰아서 확인한다(지원자 결정).

- [ ] `packages/tokens`가 라이트·다크 색, 글꼴, 간격, 선, 모서리 토큰을 내보내고, React Native·DOM API를 import하지 않는다
- [ ] 웹이 토큰에서 만든 CSS 변수를 `:root`에 두고, 페이지 CSS에는 색·`font-family` 리터럴이 없다
- [ ] 앱이 같은 토큰을 상수로 쓰고, 화면 코드에 색 리터럴이 없다
- [ ] 단위 테스트: `up`·`down`·`ink`·`muted`가 `paper`·`paper-2`·`sheet` 위에서 라이트·다크 모두 대비 4.5:1 이상이다(목업에서 처음 고른 상승 빨강이 선택된 행 위에서 3.63:1로 걸렸다)
- [ ] 웹은 Hanken Grotesk, Newsreader, IBM Plex Mono를 로드한다
- [ ] **(기기)** 앱은 Expo Go에 포함된 `expo-font`로 같은 글꼴을 로드하고, 준비될 때까지 스플래시를 유지한다
- [ ] 웹 화면이 Hallmark 검사 두 단계에서 FAIL 0이다: ① 소스 파일 모드(`apps/web/src/app`, CSS 규칙) ② `--url --render`(대비·화면 폭). 남는 REFLEX는 PR에 이유를 적고 waive한다. `--url`만으로는 CSS 규칙을 보지 않는다(#8에서 템플릿 페이지도 clean으로 나오는 것을 확인)
- [ ] `CLAUDE.md`에 웹 화면 PR 전 Hallmark 검사(설치 방법과 명령)를 적고, 웹 화면 PR 본문에 검사 결과 줄을 붙인다

## 6. 범위 밖
- 테마 전환 버튼, 사용자별 테마 저장
- 앱 화면의 자동 검사(Hallmark 검사는 CSS 기준이라 RN 화면은 사람이 같은 원칙으로 확인한다)
- 한글 웹폰트 로딩

## 7. 결정 기록
- **Almanac을 고른 이유**(지원자): 숫자를 소수점에 맞춰 세우고 선 두 굵기로 구분하는 "참고서" 재료가 시세 표에 맞다. Console(흑연 다크)과 비교해 골랐다
- **강조색 마젠타를 뺀 이유**(설계자 판단): 상승 빨강과 헷갈린다. 이 앱에서 색은 상승·하락만 뜻한다. 선택 표시는 바탕 한 단계와 왼쪽 2px 잉크 선으로 한다
- **상승 빨강·하락 파랑**(설계자 판단): 한국 사용자 관례. 지원자가 반대하지 않음
- **한글을 시스템 고딕으로**(설계자 판단): 한글 웹폰트는 용량이 크고 앱 번들(EAS Update)에도 부담이 된다. 목업에서 이 조합을 지원자가 확인했다
- **Expo 웹 미리보기는 SPA(`web.output: single`)**(설계자 판단): 템플릿 기본값 `server`는 서버에서 먼저 렌더링해 `useColorScheme()`이 라이트로 고정되고 다크에서 하이드레이션이 어긋났다(#8 화면 확인). 앱의 웹 출력은 결과물이 아니라 확인 도구라 서버 렌더링이 필요 없다
- **Hallmark 검사는 로컬에서**(설계자 판단): sloplint는 Hallmark 스킬에 들어 있고 저장소에는 없다. 저장소에 복사하면 "다른 프로젝트 파일을 복사한 흔적"(design.md 반목표)이 된다. CI 대신 PR 전에 로컬에서 돌리고 결과를 PR에 남긴다. 누구나 `pnpm dlx skills add nutlope/hallmark`로 같은 검사를 재현할 수 있다
- **Hallmark는 검사 도구로만 쓴다**(설계자 판단): Hallmark의 페이지 생성 흐름은 자체 `tokens.css`를 만들어 공유 토큰 패키지와 충돌한다. 원칙은 이 문서에 우리 말로 옮기고, 웹은 `sloplint`로 검사한다
