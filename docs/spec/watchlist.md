# 관심 종목

- 상태: 확정
- 관련 이슈: #13, #14 (spec 작성 #6)

## 1. 목적
고정된 관심 종목 10개의 현재가와 등락률을 한눈에 보고, 종목을 골라 상세로 들어간다.

## 2. 화면
| 플랫폼 | 화면 | 구성 |
|---|---|---|
| 웹 넓은 화면(60rem 이상) | `/`, `/stocks/{ticker}`의 왼쪽 열(340px) | 표: 종목(티커 + 종목명), 현재가, 등락률. 선택된 종목 행 강조. 오른쪽은 `stock-detail.md` |
| 웹 좁은 화면 | `/` | 같은 표가 화면 폭을 채운다. 행을 누르면 `/stocks/{ticker}`로 이동 |
| 앱 | 첫 화면(Expo Router `index`) | 같은 표 구성. 행을 누르면 상세 화면으로 이동 |

공통 머리: 서비스 이름과 "시뮬레이션 시세입니다. 실제 시세가 아닙니다" 문구. 목업: 브레인스토밍 A안(지원자 선택).

### 표 규칙
- 종목 칸: 티커(Plex Mono 500)와 그 아래 종목명(`muted`, 한 단계 작게)
- 현재가: Plex Mono, 오른쪽 정렬, 소수 둘째 자리
- 등락률: 부호 포함(`+0.81%`), 상승 `up`, 하락 `down`, 0이면 `ink-2`
- 표 머리 아래 2px `rule-2`, 행 사이 1px `rule`
- 선택된 행: `paper-2` 바탕 + 왼쪽 2px `ink` 선. 색으로 선택을 표시하지 않는다
- 목록에 작은 차트(스파크라인)를 넣지 않는다. 차트는 상세에 하나만 둔다

## 3. 데이터
- `useQuotes()`(전체 목록). 스키마·출처·갱신 주기는 `market-data.md`
- 목록 순서는 `packages/market`의 고정 순서를 따른다

## 4. 동작 규칙
| 상태 | 웹 | 앱 |
|---|---|---|
| 로딩(처음) | 10행짜리 뼈대. 행 높이와 칸 폭이 실제 표와 같아 값이 들어와도 밀리지 않는다 | 같음 |
| 빈 값 | 해당 없음(고정 목록). API가 빈 배열을 주면 오류로 처리한다 | 같음 |
| 오류(값이 아직 없음) | "시세를 불러오지 못했습니다"와 "다시 시도" 버튼 | 같음. 오프라인이면 "오프라인입니다"(오류가 아니라 `fetchStatus: "paused"`로 판정) |
| 오류(값이 있었음) | 마지막 값을 유지하고, 머리에 "N초 전 시세"를 표시한다. 다시 받으면 지운다 | 같음 |
| 값 갱신 | 숫자만 바뀐다. 깜빡임·색 번쩍임 없음 | 같음 |
| 장 마감 시간 | 해당 없음(24시간 시뮬레이션) | 같음 |

- 행 전체가 링크다. 키보드로 행에 초점을 옮기고 Enter로 들어간다. 초점 표시는 즉시 보인다
- 초당 바뀌는 가격은 스크린리더에 알리지 않는다(소음). 행의 접근성 이름은 "AAPL Apple, 231.42달러, 0.81% 상승"처럼 읽히게 한다
- 웹 좁은 화면(375px)에서 표가 화면 밖으로 넘치지 않는다

## 5. 수용 기준
앱 화면은 Expo 웹 미리보기(`expo start --web`)로 배치·색·차트를 확인한다. **(기기)** 표시 기준은 브라우저로 판정할 수 없는 네이티브 동작이라, 안드로이드 기기를 쓸 수 있을 때 #4와 함께 몰아서 확인한다(지원자 결정).

- [ ] 웹 `/`와 앱 첫 화면에 10종목이 고정 순서로 나오고, 1초마다 값이 바뀐다
- [ ] 등락률 부호와 색이 §2 규칙대로다(상승 빨강, 하락 파랑, 0은 잉크)
- [ ] 로딩 뼈대에서 값으로 바뀔 때 레이아웃이 밀리지 않는다(웹 CLS 0)
- [ ] API를 막았을 때 오류 화면과 "다시 시도"가 나오고, 다시 시도로 회복한다
- [ ] **(기기)** 앱이 오프라인이면 "오프라인입니다"가 나오고, 연결되면 자동으로 다시 받는다
- [ ] 값이 있는 상태에서 API가 실패하면 마지막 값과 "N초 전 시세"를 보여 준다
- [ ] 웹 넓은 화면에서 선택된 종목 행이 §2 방식으로 강조된다
- [ ] 키보드만으로 행을 골라 상세로 들어갈 수 있다(웹)
- [ ] 웹 `/`가 Hallmark `sloplint --scope app` FAIL 0이다(375px 포함)

## 7. 결정 기록
- **목록과 상세를 한 화면에(A안)**(지원자 선택): 목록 페이지와 상세 페이지를 따로 두는 B안과 목업으로 비교했다. B안은 열이 더 들어가지만, 종목을 바꿀 때마다 뒤로 가야 하고 375px에서 표가 넘쳤다
- **스파크라인 없음**(설계자 판단): "차트는 크게 하나"(Almanac). 열 개의 작은 선은 장식에 가깝고 매초 다시 그리는 비용도 든다
- **깜빡임 없음**(설계자 판단): 초당 갱신에서 번쩍이는 효과는 화면 전체를 시끄럽게 만든다. 상태만 표시한다
